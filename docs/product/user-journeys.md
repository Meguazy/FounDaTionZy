# User journeys

Project journeys: TBD(project). Use stable `J-NNN` IDs and link each journey
to requirements in [the baseline](project-specification.md).

For each real journey, describe:

1. Actor, goal, authority, and preconditions.
2. Trigger and normal user-visible steps.
3. System decisions and authoritative data changes.
4. Success outcome and acceptance evidence.
5. Validation failures, unavailable dependencies, and denied operations.
6. Interruption, retry, duplication, correction, and recovery where applicable.

Include at least one normal path and the important exception/recovery paths.
Do not document only the attractive demo. Mark illustrative examples explicitly;
they are not accepted application behavior.

# Architecture decision index

No project ADR has been created or accepted yet. The conventions of the template
are explained in [the rationale guide](../../guides/conventions-and-rationale.md);
they are not evidence that an application technology has been selected.

Copy [the ADR template](adr-template.md) to `AD-NNN-topic.md`, using the next
unused identifier, and add it below. Preserve identifiers across supersession.

| ID / record | Decision | Decision status | Decide by | Implementation / evidence |
| --- | --- | --- | --- | --- |

A proposed ADR must have an owner and `Decide by` boundary matching its affected
roadmap step or another explicit gate. At the boundary, resolve it or record an
owner-directed deferral with consequences and a new deadline.

Accepted records need actual owner direction or an explicitly delegated decision
authority. Record acceptance independently from implementation evidence.
Use a new superseding record when changing an accepted decision; preserve the
old context and link both directions. Update relevant arc42 views, requirements,
workflow contracts, ODs, and roadmap in the same change.
